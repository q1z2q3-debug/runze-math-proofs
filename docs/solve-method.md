# 应试法：把背景知识变成筛选器，再去找反例

> 这份文件不是"知识地图"，而是**解题用的工具书 + 一个已经跑过的定向搜索**。
> 目标单一：找到 `OPT ≥ ⌈LP⌉ + 2` 的显式整数实例（即 MIRUP 的反例）。
> 结论先说：**没找到**。但搜索从"随机采样"升级成"带必要条件的定向搜索"，且把
> 真正的障碍定位成了一句话——**块隔离悖论**（第 4 节）。

---

## 1. 应试知识体系：六个能直接用的工具

| # | 工具 | 内容 | 卡住什么 / 怎么用 |
|---|---|---|---|
| T1 | 配置 LP 与其对偶 | `LP = min Σx_p` s.t. `Σ_{p∋i} x_p ≥ 1`；对偶 `max Σy_i` s.t. `y ≥ 0, Σ_{i∈p} y_i ≤ 1` | 上界用分数覆盖，下界用对偶权重。**任何想证明的下界，都要落成一个可写下的 `y`** |
| T2 | DFF（对偶可行函数） | `f:(0,1]→[0,1]` 满足 `Σf(a_i) ≤ f(1)` 对所有可装集 | 造下界最便宜的路：`Σf(a_i) > B·f(1)` ⇒ 至少要 `B+1` 箱。对偶权重的"原始形态" |
| T3 | 加法间隙语言 | `OPT = ⌈LP⌉ + c`；IRUP 断言 `c=0`，MIRUP 断言 `c ≤ 1` | 目标函数可直接写成 `c`，搜索有明确标量 |
| T4 | 边覆盖/匹配 LP 的整性 | 每箱 ≤2 件时，配置 LP ≡ 边覆盖 LP，间隙在每个奇连通分量 ≤ 1/2 | 这是"小结构天花板"的根：想拿 `+2` 就绝不能停在"每箱 ≤2 件"的层面 |
| T5 | 加法硬度 / gadget 耦合 | 把多个 `+1` 组件拼起来，同时让残量不可共享（论文用 ratings + 概率权重 `g ≈ 1/(16(R+1)^m)`） | 唯一被证明能突破 `+1` 的机制；也是分母爆炸的来源 |
| T6 | 证书整数化 | 任何实数证书都能乘分母 `D` 变成 ℕ 证书（`lpVal_le_of_natCover` / `le_lpVal_of_natDual`） | 让结论可被 Lean 内核 `decide` 吃掉；`instC` 用 `D=3` 与 `D=28` 已经做到 |

**T4 是自己的推导，值得单独记**：取 `k=2`（每箱最多两件），配置 LP 就退化成"把件配成对"的分数匹配，
其整性间隙在每个奇分量至多 `1/2`；而 `+2` 需要至少 4 个"半格"同时兑现，且这些半格不能共享残量。
这解释了为什么随机/格架采样（39,150 + 729 例）全部趴在 `0`。

## 2. 已知 `+1` 实例的共同点（三条必要条件，可当筛子）

以 `instC = ([4,6,6,9,16,29,32,37,40,62], L=81)` 为标尺（这是本仓库唯一内核验证过的 `+1` 点）：

| 条件 | 内容 | `instC` 的取值 | 作用 |
|---|---|---|---|
| **N1 体积近紧** | `Σ sizes ≤ ⌈LP⌉·L`，且 `slack = ⌈LP⌉·L − Σ` 小于最小件 | `243 − 241 = 2 < 4` | 任何 `⌈LP⌉` 箱的装箱都必须"几乎无残量"，没有余地挪动 |
| **N2 结构冲突** | 存在件 `a`，使含 `a` 的箱残量装不下任何"必需件" | 62 的箱剩 `19`，装不下 40/37/32/29 | 差距不是体积造成的，是**最大件与残量的冲突**造成的 |
| **N3 LP 非整可解** | LP 最优解必须真用分数权重，且不能整化成 `⌈LP⌉` 箱 | `x = X/3`，权重含 `1/3`、`2/3` | 若 LP 能整化，`OPT ≤ ⌈LP⌉`，gap 直接归零 |

**筛子的威力**：随机实例里绝大多数是因为 `slack` 很大（几百）而 gap 恒 0；把 N1 先套上，
`n=10, L=60` 的候选空间立刻掉两个数量级。

## 3. 定向搜索（跑过，可复算）

脚本 `scripts/gap_hillclimb.py`：目标函数 `c = OPT − ⌈LP⌉`，次目标 `slack` 小、`LP` 分数性强；
单点移动改一个尺寸 `±1..±4`；`L=60, n=10, sizes ∈ [11,30]`；每个实例用 HiGHS 精确求 LP 与 MILP（`mip_rel_gap=0`）。

结果（`data/gap_hillclimb.log` / `data/gap_hillclimb.json`）：

```
restarts   = 400（420 秒）
c ≥ 1 命中 = 0
观察到的最优形态：LP = 3.000, OPT = 3, slack = 0（"完美装满"）
              LP = 3.000–3.43, OPT = 4（⌈LP⌉ = 4，仍然 c = 0）
```

也就是说：**只要 `⌈LP⌉ = OPT`，`c` 永远是 0**；爬山把实例反复推到"体积刚好装满"，
而这恰恰是 `c=0` 的那一端。`instC` 那种 `LP=3, OPT=4` 的点不是尺寸山脉的局部极值，
是**结构设计出来的**——所以纯尺寸扰动到不了。

## 4. 真正的障碍：块隔离悖论

要 `c=2`，最自然的想法是"两个 `+1` 块拼起来"。但：

- **拼接即共享（已实测）**：把两个块直接并成一个实例，两块的件可以同箱混装，残量互通。
  `instC ∪ instC`（20 件，`L=81`，体积 `482`）：实测 `LP = 6.0`、`OPT = 6`、**`c = 0`**。
  这是严格的两端夹逼：体积给 `LP ≥ 482/81 = 5.95 ⇒ OPT ≥ 6`，又给出了一个 6 箱装箱 ⇒ `OPT = 6`。
  也就是说，`+1` 的 gap **在拼接时被彻底抹平**，不是"变成 +1"，是"变成 0"。
- **隔离即整化**：要禁止混装，得用 `> L/2` 的大件把每个块"钉"在自己的箱里；
  可一旦每箱只剩 1 件大件 + 固定填料，配置 LP 就**整化**了（N3 破裂），`c` 归 0。

这个悖论就是 MIRUP 能撑 20 年的原因，也是 OpenAI 构造为什么必须引入
`P₀ = 100¹¹`、`K ≈ 1.25×10¹³`、`g = 1/(16(R+1)^m)` 这类"分数评级"机制：
**它要让残量在 LP 里"看起来可共享"、在整数解里"实际上不可共享"**，而这需要极细的尺寸分辨率——
分辨率越细，分母越大，越写不进 `l : Fin n → ℕ`。

于是本次任务的三层结论可以合并成一句：

> `+1` 已于 2026-09 被 OpenAI 反证；`+2` 的显式小实例**不存在公开样本**；
> 本仓库的贡献是：把"该往哪里找"从"随机"收敛到"必要条件 + 定向爬山"，并把它跑成 0 命中。

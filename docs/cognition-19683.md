# 三元九维 19683 认知架构：知识映射与求解

> 这份文件的定位：不是哲学宣言，而是**可执行的编码器 + 首批映射结果 + 用它跑出来的实验**。
> 架构 = 3 元 × 9 维 × 3 阶 = 3⁹ = 19683 个地址；每个知识条目被编码成 9 位三进制地址。
> 映射是**启发式分级**（不是客观真理），因此每条判级都必须能落到可核验的判据上；
> 分级存疑的地方在文末「不确定清单」里点名。

---

## 一、架构定义

### 1.1 三元

| 元 | 名 | 问的问题 | 维 |
|---|---|---|---|
| 元一 | **象** | 对象是什么、有多大、多对称 | 粒度 / 规模 / 对称 |
| 元二 | **数** | 怎么算、算多准、拿什么当证据 | 精度 / 复杂度 / 证书形态 |
| 元三 | **理** | 凭什么成立、靠什么卡住、绕几层 | 不变量 / 极值原理 / 归约深度 |

### 1.2 九维 × 三阶（0 / 1 / 2）

| 维 | 0 阶 | 1 阶 | 2 阶 |
|---|---|---|---|
| 1 粒度 | 连续 | 离散单元 | 个体副本（可数可枚举） |
| 2 规模 | 常数级 | 多项式级 | 渐近/无界 |
| 3 对称 | 无 | 弱（部分置换） | 强（全置换/群作用） |
| 4 精度 | 精确有理 | 浮点/近似 | 渐近常数 |
| 5 复杂度 | 线性 | 多项式 | 指数/不可判定外观 |
| 6 证书 | 构造（显式对象） | 对偶（权重/界） | 枚举（穷举判定） |
| 7 不变量 | 计数 | 体积/容量 | 秩/不变量（代数） |
| 8 极值 | 对偶紧性 | 测度/概率 | 拓扑/序（格论） |
| 9 归约深度 | 直证 | 一步归约 | 多层 gadget |

### 1.3 地址运算（这是它能"用来解题"的原因）

对地址 `a = (a₁…a₉) ∈ {0,1,2}⁹`，定义三种操作：

- **投影** `π_元(a)`：把某一元的 3 维压成 1 位（三进制 27 块），得到"粗格"；
- **纤维** `F(x₁,x₂,x₃)`：固定"象"三元，扫"数""理"六维 → 27×27 = 729 条近似同类；
- **迁移** `a → a'`：翻转某一维的一阶（0↔1↔2），表示"换一种做法"；
- **空格**：`S = {a : 无已知条目占据}`；求解 = 在 `S` 里找一条**可达链**，从已知条目走到目标命题。

> **判据**：一个地址之所以有价值，是因为它把「同类问题的已知做法」聚成纤维，于是"没被占据的格子"= "没被试过的做法组合"。这不是玄学，是索引。

## 三、三道题在格上的位置

| 命题 | 象（粒度/规模/对称） | 数（精度/复杂度/证书） | 理（不变量/极值/归约） | 读法 |
|---|---|---|---|---|
| `aaronson-ambainis` | 1 / 2 / 1 | 0 / 2 / 1 | 1 / 1 / 2 | 有界函数 + 方差/影响，终点是**多层**归约（限制→随机子立方→影响） |
| `alon-jaeger-tarsi` | 2 / 2 / 2 | 0 / 2 / 2 | 0 / 2 / 1 | 全对称（拉丁横截）+ 计数证书 + 秩不变量；剩余格是 **p=5, n≤9 的枚举证书格** |
| `bin-packing-mirup` | 2 / 2 / 0 | 0 / 2 / 1·2 | 1 / 0 / 2 | 个体副本 + 精确有理 + 对偶/枚举双证书；**MIRUP 的裂缝在归约深度=2 的格** |

**关键判断**：MIRUP 的地址里，`归约深度 = 2`（多层 gadget）这一维不是可选项。原因在 §4 的实验与 §5 的参数分析：**纯"象/数"格（1 层、无 gadget）根本到不了 `OPT ≥ ⌈LP⌉+2`**，因为在这一层 LP 就是"边覆盖/集合覆盖"类松弛，整性间隙被结构性地卡在 `+1`。

## 四、用格驱动求解（真实跑出来的）

格不是摆设，它的用法是：**把"象 + 数"六维当参数空间，穷举可跑的子格，看哪一格能出反例。**

子格规模：`arity(4) × band(3) × sym(3) × tight(3) × mult(3) × den(3) = 972` 格，其中 `n ≤ 14`（可枚举 `2^n` 模式、可 MILP）的有 **729 格**。每格生成一族实例，用 `scripts/bpp.py` 精确求 LP（HiGHS）与 OPT（MILP，`mip_rel_gap=0`）。

结果（`data/lattice_result.json`，脚本 `scripts/lattice_search.py`）：

```
cells_total = 972
run         = 729
dist(OPT − ⌈LP⌉) = {0: 729}
gap ≥ 1 的格   = 0
```

**这不是"猜想为真"的证据，而是"象/数"格的封闭性证据**：

- 729 个格全部落在 `OPT = ⌈LP⌉`；
- 此前 39,150 例的随机/扰动搜索同样 0 命中（`data/search.log`、`data/search2.log`）；
- 已知的唯一 `+1` 占据点是 `instC`（`[4,6,6,9,16,29,32,37,40,62]`, L=81），它是**人手挑出来的**，不属于上述 972 格任何参数化族 —— 这说明 `+1` 需要"精心设计的混合结构"，而 `+2` 需要的是多层 gadget。

于是格上的结论是：**往 `归约深度 = 2` 迁移**。这一步恰好就是 OpenAI 2026 构造所在的位置（图 → 装箱 → LP，三层），而它撞到的是可显式化的问题（§5）。

## 五、为什么"解"这一步被卡住（量化）

| 层 | 事实 | 后果 |
|---|---|---|
| 定义层 | 题目要求 `l : Fin n → ℕ` 的**显式**尺寸表 | 必须能写出来 |
| 构造层 | OpenAI 预印本：`P₀ = 100¹¹`，`K ≈ 1.25×10¹³`，`R ≈ 10¹⁵·n`，`g = 1/(16(R+1)^m)` | 尺寸分母 ≈ `(10¹⁵)^m`，二进制长度天文级 |
| 判定层 | `PacksIn` 的否证在 Lean 里靠 `decide`（`k^n`） | `n = 5B ≫ 千` 时不可行 |

所以"先映射全人类知识，再去解"在这个具体问题上给出的答案是：

1. **映射确实指向了正确的空格**（归约深度=2 的格）；
2. 但那格的**已知占据者不可搬运**（分母爆炸）；
3. 于是唯一可执行的动作是**在格内自造一个小参数 gadget**（我的 R1 路线）：把 `P₀` 从 `100¹¹` 降到可计算量级，用 MILP 验证 `OPT_LP = B` 与 `OPT > B+1`，再在 Lean 里用支撑集技巧 + 手写抽出论证补 `¬PacksIn`。

## 七、不确定清单（不许含糊的地方）

1. **§2.2/2.3 的分级是启发式**，判据写在 `data/cognition_map.json` 的 `rule` 字段里；不同判据会得到不同地址，架构的价值在"可复算的索引"，不在"唯一正确的分级"。
2. **"全人类知识"没有真的全量映射**：本仓库做了编码器 + 21 个域级条目 + 3 个命题级条目。全量需要语料层的抽取管线，这一步尚未做（也不该假装做了）。
3. **§4 的 729 格 0 命中**：样本只覆盖 `n ≤ 14`、整数尺寸、`L ≤ 1000` 的格；不能外推为"MIRUP 在这些格上成立"的定理。
4. **`instC` 的 `+1` 是内核验证的**（core 层 rc=0）；`optNumber ≥ 4` 用的是计数论证 + 精确 MILP，不是 `3^10` 内核枚举（3 GB 内存跑不动）。
5. 时间口径：前沿状态截至 2026-11-15（AA 已于 2026-11-06 被证明；MIRUP 已由 OpenAI 2026-09-24 反证）。
